# Playground

Закрытая платформа для трёх разработчиков. Текущий этап: M1 — аккаунты и портал. Работают вход, роли, управление командой и доступ к библиотеке. Добавление игр, комментарии, сборки и сам Vault будут добавлены следующими этапами.

## Локальный запуск

Нужны Node.js 22.13+ и pnpm 10.34.5. Если pnpm отсутствует, используйте `npx --yes pnpm@10.34.5` вместо `pnpm`.

```powershell
npx --yes pnpm@10.34.5 install --frozen-lockfile
Copy-Item .env.example .env
npx --yes pnpm@10.34.5 dev
```

В Linux вместо Copy-Item используйте `cp`. Адрес: http://127.0.0.1:5173. API: http://127.0.0.1:3001/api/health. Только локальный доступ. Ctrl+C останавливает процессы. Во время сна или выключения ноутбука приложение недоступно. Фонового опроса GitHub нет.

Данные хранятся в `data/database/playground.sqlite`, вне Git. DATABASE_PATH в `.env` задаётся относительно корня проекта или абсолютным путём. Миграции применяются автоматически при старте, транзакционно и однократно. Ручной запуск: `pnpm db:migrate`.

## Первый администратор

В отдельном интерактивном терминале из корня проекта:

```text
npx --yes pnpm@10.34.5 admin:create
```

Команда спросит имя и дважды пароль (вместо символов видны звёздочки). Минимальная длина пароля — 12 символов, максимальная — 128. Если поле заполнено неверно, команда объяснит причину и даст исправить это поле без перезапуска. Пароль не передаётся в аргументах команды, не сохраняется в Git и не выводится в лог. Команда работает только до создания первого пользователя. Дефолтного пароля и публичной регистрации нет.

Обновите страницу и войдите. При первом входе обязательно замените начальный пароль. В разделе **Команда** администратор может создавать аккаунты, менять роль, отключать пользователей, сбрасывать пароли, завершать сессии и назначать доступ к отдельным играм и права Vault. Новый аккаунт по умолчанию не имеет доступа к играм и Vault; администратор имеет полный доступ. После сброса пароля снова требуется его смена.

Библиотека пока пустая: создание игр появится в M2. Тестовые игры и пользователи из автоматических тестов не попадают в рабочую базу.

Используйте адрес **http://127.0.0.1:5173**, а не localhost: разрешённый origin задан в `.env` через `APP_ORIGIN`. При смене адреса поменяйте и APP_ORIGIN (без завершающего `/`). Подробности безопасности: [docs/authentication.md](docs/authentication.md).

## Проверки

```text
pnpm build
pnpm typecheck
pnpm lint
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

Серверные тесты проверяют API, миграции, сохранность данных, пароли, сессии, CSRF, ограничения входа и права. Браузерный тест использует временную базу и отдельные порты 5174/3002, проходит вход администратора, создание коллеги, первый вход, назначение игры, выход, восстановление сессии и мобильный экран. Для установленного Edge можно не скачивать Chromium: в PowerShell задайте `$env:PLAYWRIGHT_CHANNEL = 'msedge'` перед `pnpm test:e2e`.

## Docker и будущий VPS

```text
docker compose up --build -d
docker compose logs -f
docker compose down
```

Нужен запущенный Docker Engine. Адрес: http://127.0.0.1:8080. API не публикует внешний порт. Данные сохраняются в volume `playground-data`; обычный `down` их сохраняет. Не запускайте `down -v`, если данные нужны. Docker задаёт окружение явно и не использует локальный `.env`.

Первого администратора внутри Docker создайте через `docker compose exec api pnpm --filter @playground/api admin:create` (интерактивный терминал обязателен). Эта локальная Compose-конфигурация намеренно использует development и HTTP на loopback. Для VPS нужны отдельная HTTPS-конфигурация, `NODE_ENV=production` и реальный `APP_ORIGIN` с HTTPS. При production сервер отклоняет HTTP-origin и устанавливает Secure cookies.

Для переноса остановите приложение и скопируйте весь каталог данных (для Docker — содержимое volume) на целевой сервер. Не копируйте только SQLite-файл работающей базы: актуальные данные могут находиться в WAL. Резервную копию храните также на другом устройстве. Секреты настраиваются отдельно и не попадают в Git.

Текущая конфигурация предназначена только для локальной разработки. До открытия в интернет нужны HTTPS, отдельный origin игр, утверждённая изоляция сборок и проверенные резервные копии. Провайдер, домен и GitHub App пока не настроены.

Требования: [AGENTS.md](AGENTS.md), [DESIGN_AND_VAULT.md](DESIGN_AND_VAULT.md). Актуальный масштаб: три разработчика, допустимы медленные последовательные сборки, сначала ноутбук, затем возможен VPS.
